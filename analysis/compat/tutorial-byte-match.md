The comparison uses the original executable with SHA-256 `ccab6682b55dae14dbf104e491cfbd3b32a6280022020032ae0615500949ba59`. It does not use raw decompiler pseudocode as the expected output.

## What a match proves

Every byte in each credited procedure extent equals the original after placing named addresses in the original layout. OMF FIXUPP operands are resolved by game-function, global, CRT-helper and Win16-import identities. Compiler BAKPAT records are applied as emitted. No instruction, stack offset, branch displacement, immediate value or mismatching byte is masked or repaired. The full original extent, including unreachable generated instructions, is compared.

The three functions in the earlier [pilot](byte-match.md) remain separate matches. TODO5 now includes them and these tutorial matches in its byte-match column. Its main source-review checkboxes still reflect the independent review ledger; these results do not silently expand the 130 reviewed-function count.

Calls are bound to original addresses for comparison. This is not a linked replacement tutorial, a final-executable byte match, or acceptance of all surrounding globals/callees. No Windows interaction or tutorial playthrough was required for this compiler test. The original program is not being called to implement these candidate bodies.

## Recovery findings

- `AdvanceTutor` reproduces the step loop, bold-step changes, error suppression, end checks, title formatting and redraw calls, including jumps omitted from the decompiler presentation.
- `FCheckBtlPlan` includes an otherwise unused battle-plan pointer calculation. Its parameters suggest more validation than the original body actually performs; no additional restrictions were invented.
- `FCheckPatrolWP` preserves the original distance check and unused plan parameter. `FCheckFleetName` preserves the unusual missing-fleet/name return paths.
- Local declaration ordering and identifier storage lengths affect the unoptimized compiler’s stack allocation. Some candidate basenames, length-preserving names, and preprocessor aliases are retained. The clean rebuild, not an assumption about naming, establishes each match.
- Source cleanup temporarily disturbed two stack layouts; those candidates were not credited until their cleaned sources were rebuilt and compared successfully.

## Reproduction and checks

See [compat/tutorial-match/README.md](../../compat/tutorial-match/README.md) for the clean build and evidence commands. The generated batch deletes stale outputs and stops on compiler errors. Each file has a separate build log. The committed regression fixture contains our compiler objects/listings; the original executable remains the independent expected source.

`tests.test_tutorial_byte_match` reproduces all 24 outcomes and checks current source/header/object hashes. Negative controls change an instruction, move a global reference, remove its mapping, and shorten the expected extent; none can receive a byte-match result. The TODO renderer also rejects stale source hashes. Existing pilot and runtime-library parser tests are run with this suite.
