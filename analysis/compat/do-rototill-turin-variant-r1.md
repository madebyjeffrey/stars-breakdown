# Rototill selector-3 versus Turin selector-1 retained turn

Status: **input and output comparison for full-turn harness reuse; RT-E4 open**.

The [machine-readable audit](do-rototill-turin-variant-r1.json) is generated by
[`tools/rototill_turin_variant_audit.py`](../../tools/rototill_turin_variant_audit.py)
from the original Turin control run `runs/vmctl-sye3k0/` and the original
Rototill run `runs/rototill-original-turn-r1/`. It pins source hashes and
compares decoded records in turn order. The [audit test](../../tests/test_rototill_turin_variant_audit.py)
recomputes the result.

| File | Input difference | Identical turn-1 records in order |
|---|---|---:|
| HST | Player record 2, byte 7: `27` → `67` | 69 of Turin 83 / Rototill 87 |
| M1 | Byte identical | 30 of 32 / 32 |
| M2 | Player record 1, byte 7: `27` → `67` | 14 of 24 / 28 |
| XY | Byte identical | Byte identical |

The extra four turn-1 M2/HST records are two type-16/type-20 fleet/order
pairs. The audit also records the exact changed record-index ranges and kinds:
HST includes planet, production, fleet, design, and wormhole differences;
M2 includes player, planet, production, design, score, and fleet/order
differences. M1 has its game and one planet record changed. The comparison
does not assign causation to each downstream difference.

The existing [`satisfy_orders_turin_binding_e3_probe.c`](../../tests/satisfy_orders_turin_binding_e3_probe.c)
and its [test driver](../../tests/test_satisfy_orders_turin_binding.py)
already materialize the shared input through a complete reconstructed
selector-1 turn and compare generated streams with the Turin originals.
That harness provides the reusable game-input, movement, production,
serialization, and output-diff machinery. RT-E4 now needs a selector-3
personality dispatch using the same retained input, with Rototill production
and fleet callbacks bound to the live tables. The result must be compared
against the [Rototill turn oracle](do-rototill-turn-r1-oracle.json) and the
full original streams. Retained compact records cannot prove live PLORD,
AI-table pointer identity, or RNG state by themselves.
