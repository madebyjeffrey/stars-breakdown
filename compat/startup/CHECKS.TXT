START2A MANUAL ACCEPTANCE - USE SYNTHETIC TEST RACES

[ ] Run START.EXE. Check the artwork, version text and Race Workshop button.
[ ] Open Race Workshop with the button, or F6 / Alt+W.
[ ] Race > New Race: enter a name and plural, then try another predefined
    race. Check that the name, illustration and advantage points update.
[ ] Visit all six pages. Try primary/lesser traits, the habitability controls,
    growth, factories/mines and research choices. Try Next and Back.
    Some custom settings legitimately leave negative points and cannot save.
[ ] On page 4, Gravity has a blue range, Temperature red, Radiation green.
    Move/widen a range and check that its colored fill follows the controls.
    Immunity intentionally removes that range's colored fill.
[ ] Select a predefined race for a valid baseline, rename it to Pioneer /
    Pioneers, Finish, and save as a NEW PIONEER.R1 in the package directory.
[ ] Race > Open Race: open PIONEER.R1. Confirm names, traits and points.
[ ] Make a temporary change and Cancel. Reopen the file; the saved version
    should be unchanged. Cancel a Save dialog too; no new file should appear.
[ ] Open a disposable invalid file with Open Race (All Files). Check that an
    error is displayed and you can return to the workshop.
[ ] Open your new PIONEER.R1 with the original Stars!: launch the original
    with the race file as its command-line argument, or use its file picker.
    Confirm the same race. Save a separate copy as ORIGIN.R1, then open that
    copy in START2A. Report any differences.
[ ] Help > Settings: change a font or a startup preference, Save, exit and
    restart. Confirm it persisted. Restore your preferred setting afterward.
[ ] Try resizing/moving the workshop, switch to the starting screen and back,
    then exit/restart. Report clipped text, wrong colors or graphical debris.
[ ] Run the automatic check and, optionally, the broader REGRESS test.

Use your physical mouse as usual. Keyboard navigation is also available.
If mouse and keyboard behave differently, describe the control and action.
Include the page number, expected result and actual result in your notes.
Return failures too. The completed package and logs are useful evidence even
when something does not match.
